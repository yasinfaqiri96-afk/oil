# MASHAL: مبنای تست و اندازه‌گیری

مبنای کد: `73344bef35a7103b8e717b9849ec5cf345e0e3da`، شامل اصلاح آواتار روی نسخهٔ گزارش `b7cea8a4de2d1589c79f61b9055e83eb5d9c998b`.

## محیط و Build

- SDK .NET 8 در Docker، PostgreSQL 16 محلی؛ هیچ اتصال Production استفاده نشد.
- یک Build پروژهٔ تست با تمام project referenceها: موفق، صفر خطا، ۱۸ هشدار، ۲ دقیقه و ۴۱٫۹۳ ثانیه.
- هشدارها شامل تشخیص‌های قبلی C#/Razor و NU1900 هستند. بسته‌ها از cache بازیابی شدند؛ خوراک بررسی آسیب‌پذیری NuGet در این اجرا در دسترس نبود.
- Suite کامل با DLL همین مبنا، پیش از اصلاح انتظارهای تست، اجرا شده است. نتیجهٔ دقیق پس از ختم اجرا در همین سند ثبت می‌شود.
- آثار خام خارج مخزن در `/workspace/mashal-artifacts/baseline/` نگهداری می‌شوند؛ رمز اتصال در فایل جدا با مجوز 600 است و جزو مستندات/Commit نیست.

## روش اندازه‌گیری قابل تکرار

`DatabaseOperationPerformanceTests` چهار سناریو روی PostgreSQL موقت اجرا می‌کند: واردکردن ۱۰۰۰ بارگیری و رسید گروهی ۱۰۰۰ بارگیری، هرکدام با حسابداری فعال و غیرفعال. مسیر واقعی Controller، Audit و آداپتر حسابداری استفاده می‌شود. Setup، Seed و Queryهای بررسی از زمان عملیات جدا هستند.

برای هر اجرا این معیارها گزارش می‌شوند: میلی‌ثانیه، تعداد فرمان‌های دیتابیس، تراکنش، SaveChanges، اوج تعداد Entityهای دنبال‌شده در زمان ذخیره، و بایت تخصیص‌یافتهٔ GC در تمام threadهای فرایند طی عملیات. این بایت، حافظهٔ ساکن یا اوج Working Set نیست. Collection اجازهٔ اجرای موازی این تست‌ها را نمی‌دهد. هیچ حد زمان وابسته به دستگاه برای سبزکردن یا شکست تست استفاده نشده است.

بررسی‌های پس از عملیات شامل تعداد اسناد، مقدار کل، Audit، روابط منبع، نبود موجودی مصنوعی در واردکردن، هویت یکتای SourceEventId، توازن هر سند مالی و مقدار/ارزش pool موجودی است. مسیر حسابداری فعال در کد مبنا باید نقص A01 را با فقدان Journal رسید گروهی آشکار کند؛ آن را موفقیت کامل اعلام نمی‌کند.

مسیر `Bulk_SetBased_Conversion_Cost` نیز اندازهٔ ۱۰۰۰ ردیف را علاوه بر اندازه‌های قبلی پوشش می‌دهد. تبدیل بارگیری به حمل یک جابه‌جایی منبع است؛ این benchmark ادعای سنجش ثبت خرید یا رسید حسابداری ندارد.

پس از Build تازهٔ پروژهٔ تست:

```bash
dotnet vstest tests/PTGOilSystem.Web.Tests/bin/Debug/net8.0/PTGOilSystem.Web.Tests.dll \
  '--TestCaseFilter:FullyQualifiedName~DatabaseOperationPerformanceTests|FullyQualifiedName~Bulk_SetBased_Conversion_Cost' \
  '--Logger:trx;LogFileName=database-performance.trx' \
  --ResultsDirectory:artifacts/test-results
```

اتصال `PTG_TEST_POSTGRES_ADMIN` باید به PostgreSQL آزمایشی با مجوز ساخت دیتابیس اشاره کند. fixture نام آزمایشی را با DatabaseSafetyGuard کنترل می‌کند، migration را فقط در دیتابیس جدید آزمایشی اجرا می‌کند و همان دیتابیس را پس از تست حذف می‌کند.

هنوز عدد قبل/بعد برای فروش گروهی، مصرف گروهی، صفحهٔ چرخهٔ قرارداد و گزارش مانده از این harness استخراج نشده است. سرعت parserِ Excel به معنی سرعت ثبت واقعی واردکردن نیست. نتایج محیط محلی نیز پیش‌بینی زمان VPS یا شبکهٔ مشتری نیستند.
