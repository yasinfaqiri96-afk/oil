# مرحلهٔ پنجم: ناوبری روشن‌تر چرخهٔ قرارداد

## بررسی و دامنهٔ اصلاح

نسخهٔ فعلی پیش از این اصلاح هفت تب خرید داشت. «بارگیری و رسید» و «حمل و نقل» از قبل دو مسیر مستقل را با companion section در یک نمای مشترک نشان می‌دادند. این منطق، صفحه‌بندی، مجوزها، پیوندهای بازگشت و بارگذاری تنبل حفظ شدند؛ تغییر دوبارهٔ کنترلر یا موتور گزارش ضرورت نداشت.

ناوبری موجود اکنون با سه عنوان «نمای کلی»، «بارها و عملیات» و «مالی و مصارف» واضح‌تر است. هر هفت مقصد خرید و هر سه مقصد فروش باقی مانده‌اند. گروه‌بندی صرفاً نمایشی است؛ موجودی، کالای در راه، مقدار فروخته‌شده و حساب قرارداد با همان تعریف‌های قبلی محاسبه می‌شوند. عنوان کارت‌های چرخه، فقط وقتی تب مربوط واقعاً برای نوع قرارداد وجود دارد، به آن بخش پیوند دارد. آواتارهای سبک موجود، اسناد چاپی و منوی دفتر حساب حفظ شده‌اند.

ناوبری از لینک‌های واقعی استفاده می‌کند. نقش ناقص ARIA tab حذف شد تا رفتار عادی لینک و صفحهٔ مقصد برای صفحه‌خوان درست باشد. پس از جایگزینی ناوبری در بازشدن تنبل تب، تمرکز کیبورد روی همان لینک می‌ماند. نتیجهٔ درخواست قدیمی پس از خروج از صفحه روی قرارداد دیگری اعمال نمی‌شود.

پیش از اصلاح، خطای fetch تنها یک پیام نشان می‌داد و راه مستقیمی برای بازکردن مقصد انتخاب‌شده وجود نداشت. اکنون خطا به‌صورت alert اعلام می‌شود و لینک واقعی GET با همان قرارداد، تب و حالت قفل ارائه می‌شود. این مسیر در نبود fetch یا cache نیز کار می‌کند.

## بررسی‌های انجام‌شده

- `node --check src/PTGOilSystem.Web/wwwroot/js/contract-journey-tabs.js`
- `git diff --check`
- `node tests/browser/contract-journey-navigation.cjs` با Chromium و Playwright نصب‌شده در محیط؛ بدون افزودن dependency تولیدی.
- عرض‌های ۱۴۴۰، ۷۶۸ و ۳۹۰ پیکسل: پهنای سند از صفحه بیشتر نشد، هفت لینک و سه گروه باقی ماندند، تمرکز کیبورد حفظ شد، بازیابی خطا همان context را نگه داشت و GET جایگزین موفق بود و پاسخ دیررس صفحهٔ قبلی دور انداخته شد؛ خطای JavaScript صفر بود.

تست مرورگر CSS و JavaScript واقعی مخزن را با markup نمایندهٔ خروجی ناوبری می‌آزماید. این بررسی جایگزین Web build، تست ساختاری Razor یا بررسی صفحهٔ واقعی دارای داده نیست. دو تست ساختاری جدید به `ContractJourneyViewStructureTests` اضافه شدند. اجرای این کلاس و Razor build باید در build هماهنگ مرحلهٔ نهایی انجام شود.

اسکریپت خروجی را به `/tmp/mashal-journey-browser` می‌نویسد. برای مسیر دلخواه از `PTG_BROWSER_ARTIFACTS` و برای مسیر مرورگر از `PTG_CHROMIUM_PATH` استفاده شود. تصاویر و JSON محلی این اجرا در `/workspace/mashal-ux-artifacts` هستند و شامل اطلاعات مشتری نیستند.

## محدودیت‌های آگاهانه

گروه چهارم «اسناد و تاریخچه» به‌عنوان تب جدید ساخته نشد: در این نسخه payload و مسیر مستقل معتبر برای آن وجود ندارد. اسناد و عملیات موجود در جای فعلی خود حفظ شدند. ادغام یا انتقال آن‌ها به مسیر تازه، به بررسی مجوزها و مدل گزارش جداگانه نیاز دارد.

فرم‌های گروهی فروش و مصارف متعلق به اصلاحات همان جریان‌ها هستند و در این تغییر دست‌کاری نشدند. هیچ Entity، Migration، نرخ، حسابداری، تراکنش موجودی یا دادهٔ تاریخی تغییر نکرد.
